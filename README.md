# Дашборд воронки продаж для Битрикс24

Встраиваемое приложение для платформы [Вайбкод](https://vibecode.bitrix24.tech): показывает сводку по стадиям воронки, ключевые показатели и последние сделки портала Битрикс24.

## Что показывает

- **Три показателя:** сумма сделок в работе, количество выигранных сделок, средний чек по выигранным сделкам.
- **Сводка по стадиям воронки:** вертикальная диаграмма с переключателем «Кол-во / Сумма». Стадии без сделок выводятся с нулём.
- **Последние сделки:** название, стадия, ответственный, сумма и строка «Итого».
- **Фильтры:** воронка, ответственный, период создания сделки.

## Встраивание и авторизация

Приложение открывается внутри портала как пункт левого меню или вкладка CRM и работает от лица авторизованного сотрудника.

Портал открывает место встраивания POST-запросом с параметром `AUTH_ID`. Сервер перекладывает токен в httpOnly-cookie и отвечает редиректом на `GET /`, поэтому токен не остаётся в адресной строке, истории браузера и логах прокси. Все запросы к CRM уходят с этим токеном — сотрудник видит ровно те сделки, которые доступны ему в CRM. Кэш разделён по пользователям. Во встроенном режиме без сессии пользователя данные не отдаются (`401 NO_USER_SESSION`).

Привязка мест встраивания:

```bash
VIBECODE_API_KEY=ваш_ключ APP_URL=https://app-xxx.vibecode.bitrix24.tech \
  node scripts/bind-placements.js            # показать доступные места
  node scripts/bind-placements.js --bind     # привязать меню и вкладку CRM
  node scripts/bind-placements.js --list     # показать привязанные
```

## Запрошенные скоупы

| Скоуп | Зачем |
|---|---|
| `crm` | Сделки, воронки, стадии — весь источник данных |
| `user` | ФИО ответственных и фильтр по сотрудникам |
| `placement` | Встраивание в меню и карточку CRM |

Ключ выпускается в режиме «только чтение»: приложение ничего не изменяет в CRM.

## Безопасность

- В репозитории нет вебхуков, ключей, токенов и файлов `.env` — только `.env.example` с пустыми значениями.
- Ключ Вайбкода читается сервером из переменной окружения `VIBECODE_API_KEY` и в браузер не передаётся.
- Фронтенд обращается только к собственному бэкенду (`/api/meta`, `/api/dashboard`) — схема BFF.
- Токен сессии хранится в памяти процесса, в httpOnly-cookie, 24 часа; на диск не пишется.
- `frame-ancestors` ограничивает встраивание доменами Битрикс24.

## Структура

```
src/config.js      чтение переменных окружения
src/session.js     сессии пользователей портала (httpOnly-cookie)
src/placements.js  работа с местами встраивания
src/vibecode.js    клиент API Вайбкода: повторы, Retry-After, обработка ошибок
src/dashboard.js   сбор данных: справочники, агрегация по стадиям, показатели, сделки
src/server.js      HTTP-сервер: статика + /api/meta и /api/dashboard
public/            интерфейс (HTML, CSS, JS без сборки и зависимостей)
scripts/           привязка мест встраивания
docs/              инструкция пользователя и описание для проверяющего
```

Зависимостей нет: только стандартная библиотека Node.js 20.

## Запуск локально

```bash
export VIBECODE_API_KEY=ваш_ключ
npm start
# откройте http://localhost:3000
```

## Деплой в Вайбкод

1. **Создайте ключ** в кабинете Вайбкода: `vibe_app_…` для встраивания в портал или `vibe_api_…` для личного использования. Нужны разрешения на чтение CRM и пользователей.

2. **Создайте сервер:**

```bash
curl -X POST https://vibecode.bitrix24.tech/v1/infra/servers \
  -H "X-Api-Key: $VIBECODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"provider":"bitrix-cloud","name":"funnel-dashboard","plan":"bc-small","region":"ru-central","image":"ubuntu-24.04"}'
```

Дождитесь `status: "running"` и `blackholeStatus: "CONNECTED"` (обычно 1–3 минуты).

3. **Разверните приложение** — ключ передаётся здесь, в блоке `env`, и только здесь:

```bash
curl -X POST https://vibecode.bitrix24.tech/v1/infra/servers/SERVER_ID/deploy \
  -H "X-Api-Key: $VIBECODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "source": { "url": "https://github.com/ВАШ_АККАУНТ/b24-funnel-dashboard/archive/refs/heads/main.tar.gz" },
    "runtime": "node20",
    "install": "cd /opt/app && npm install --omit=dev",
    "start": "cd /opt/app && node src/server.js",
    "port": 3000,
    "env": { "NODE_ENV": "production", "VIBECODE_API_KEY": "ваш_ключ", "DASHBOARD_CURRENCY": "₸" }
  }'
```

4. **Проверьте:** приложение доступно по адресу `https://app-SERVER_ID.vibecode.bitrix24.tech`, служебная проверка — `/healthz`.

5. **Встройте в портал** как вкладку CRM или пункт меню — раздел «Места встраивания» документации Вайбкода.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VIBECODE_API_KEY` | — | Ключ Вайбкода, обязательна |
| `VIBECODE_API_BASE` | `https://vibecode.bitrix24.tech` | Адрес API |
| `PORT` | `3000` | Порт (в Чёрной дыре проксируется ровно 3000) |
| `DASHBOARD_CURRENCY` | `₸` | Символ валюты в подписях |
| `DASHBOARD_RECENT_LIMIT` | `20` | Сколько сделок в таблице |
| `DASHBOARD_META_TTL_MS` | `300000` | Кэш справочников |
| `DASHBOARD_DATA_TTL_MS` | `30000` | Кэш данных дашборда |

## Использованные эндпоинты API

| Данные | Запрос |
|---|---|
| Воронки | `GET /v1/deal-categories` |
| Стадии | `GET /v1/statuses?filter[entityId]=DEAL_STAGE` |
| Сводка по стадиям | `POST /v1/deals/aggregate` (группировка по `stageId`) |
| Последние сделки | `GET /v1/deals?order[createdAt]=desc&limit=20` |
| Сотрудники | `GET /v1/users` |

## Учтённые особенности платформы

- Стадии дополнительных воронок имеют префикс (`C1:NEW` против `NEW`) — сравниваются только внутри одной воронки.
- Стадии без сделок в ответе агрегации не приходят — достраиваются нулями из полного списка стадий.
- API суммирует суммы в валютах сделок без конвертации — дашборд рассчитан на одну валюту портала.
- При `QUEUE_OVERFLOW` (429) соблюдается заголовок `Retry-After`, далее — экспоненциальная задержка с джиттером.
- Если агрегация недоступна, показатели считаются на стороне приложения по выгрузке сделок.
